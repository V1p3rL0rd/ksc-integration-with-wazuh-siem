# Kaspersky Security Center → Wazuh SIEM

[English](README.md) | **Русский**

Передача критических событий Kaspersky Endpoint Security (вирусы, сетевые атаки, IOC, попытки обхода защиты) из **Kaspersky Security Center** в **Wazuh**: приём по Syslog, нормализация событий, правила и корреляция. События уровня 10 и выше уходят в настроенные в Wazuh оповещения (например, Telegram).

Проверено: KSC Linux 16.3, KES для Windows 14.1, KESL 12.4, Wazuh 4.14.5.

## 1. Требования

- Wazuh manager 4.x (один узел или master кластера), Linux с systemd, `bash`, `python3`, `iproute2`, права `root`.
- KSC Linux 16.x с веб-консолью, права администратора.
- Сетевой доступ от сервера KSC к менеджеру Wazuh по TCP 514.

## 2. Установка на менеджере Wazuh

```bash
git clone https://github.com/V1p3rL0rd/ksc-integration-with-wazuh-siem.git
cd ksc-integration-with-wazuh-siem
cp config.env.example config.env
sudo chown root:root config.env && sudo chmod 600 config.env
sudo nano config.env          # KSC_IP — адрес сервера KSC, LISTEN_IP — адрес менеджера Wazuh
```

```bash
sudo ./deploy.sh plan         # показать изменения
sudo ./deploy.sh install      # установить
```

`install` добавляет в `ossec.conf` приём Syslog от `KSC_IP`, устанавливает декодер и правила, проверяет их через `wazuh-logtest`, перезапускает `wazuh-manager`. При ошибке автоматически возвращает предыдущее состояние из резервной копии.

Если приём Syslog или файлы декодера/правил уже были настроены вручную, `plan` остановится и покажет найденное. Тогда:

```bash
sudo ./deploy.sh install --adopt
```

Параметры `config.env`:

| Ключ | По умолчанию | Описание |
|---|---|---|
| `KSC_IP` | — | IP сервера KSC (обязательно) |
| `LISTEN_IP` | — | IP менеджера Wazuh для приёма (обязательно) |
| `SYSLOG_PORT` | `514` | Порт |
| `SYSLOG_PROTOCOL` | `tcp` | `tcp` / `udp` |
| `OSSEC_DIR` | `/var/ossec` | Каталог Wazuh |
| `SERVICE_NAME` | `wazuh-manager` | Служба systemd |
| `BACKUP_ROOT` | `/root/ksc-integration-with-wazuh-siem-backups` | Резервные копии |
| `BACKUP_KEEP` | `10` | Сколько копий хранить |
| `RULE_ID_MIN` / `RULE_ID_MAX` | `100700` / `100799` | Диапазон ID правил |
| `LOG_IGNORE_REGEX` | — | Посторонние ошибки `ossec.log`, которые не считать сбоем |
| `AGENT_RECOVERY_TIMEOUT` | `180` | Ожидание переподключения агентов, с |

## 3. Настройка Kaspersky Security Center

Выполняется в веб-консоли KSC **после** установки на Wazuh.

### 3.1. Экспорт в SIEM

**Свойства Сервера администрирования → Общие → Экспорт в SIEM-систему**

1. «Экспортировать события в SIEM» → **Включено**.
2. **«Параметры»**:
   - Адрес сервера SIEM-системы — `LISTEN_IP`;
   - Порт — `514`;
   - Протокол — **TCP**;
   - Формат данных — **Syslog**;
   - Максимальный размер сообщения — **8192**.
3. Закрыть окно. Статус подключения — **«Подключено»**.
4. «Дата начала экспорта системных событий» — **не задавать**.
5. **«Сохранить»**.

### 3.2. Как отметить событие для экспорта

**Управление активами → Политики → политика → Настройка событий → уровень**

1. Отметить флажками нужные события.
2. **«Отметить для экспорта в SIEM-систему по протоколу syslog»** — в столбце Syslog появится ✓.
3. У каждого отмеченного события «Время хранения» должно быть **не «Не хранить»** (например, 30 суток), иначе событие не экспортируется.
4. **«Сохранить»**.

Настраиваются политики в группе «Управляемые устройства». Если в подгруппе есть своя политика KES — настроить и её. Политику Агента администрирования не менять.

### 3.5. Вирусная атака

1. **Свойства Сервера администрирования → Общие → Вирусная атака** → включить **«Антивирусы для рабочих станций и файловых серверов»** (10 вирусов за 10 минут) → «Сохранить».
2. **Свойства Сервера администрирования → Настройка событий → Критическое** → «Вирусная атака» → «Отметить для экспорта…» → «Сохранить».

## 4. Проверка

```bash
sudo ./deploy.sh verify
```

Сквозная проверка:

1. На менеджере:
   ```bash
   sudo tail -F /var/ossec/logs/alerts/alerts.json | grep --line-buffered '"kaspersky"' \
     | jq -c '{rule: .rule.id, level: .rule.level, desc: .rule.description}'
   ```
2. На тестовом компьютере создать тестовый файл [EICAR](https://www.eicar.org/download-anti-malware-testfile/).
3. Через 2–5 минут ожидается алерт **100701** (уровень 10) и оповещение.

Правила:

| ID | Уровень | Событие |
|---|---|---|
| 100709 | 10 | любое событие, отмеченное в KSC для экспорта |
| 100701 | 10 | обнаружен вредоносный объект |
| 100702 | 3 | лечение невозможно (объект удалён), без оповещения |
| 100710 | 13 | вредоносные объекты на 3 и более разных компьютерах за 10 минут |

## 5. Команды deploy.sh

| Команда | Действие |
|---|---|
| `sudo ./deploy.sh plan` | показать изменения, ничего не меняя |
| `sudo ./deploy.sh install` | установить / обновить |
| `sudo ./deploy.sh test` | прогнать тестовые события через `wazuh-logtest` |
| `sudo ./deploy.sh verify` | проверить состояние |
| `sudo ./deploy.sh rollback` | удалить интеграцию |

| Опция | Действие |
|---|---|
| `-c FILE` | другой файл настроек |
| `--adopt` | принять под управление вручную созданные настройки |
| `--no-restart` | не перезапускать `wazuh-manager` |
| `--from-backup DIR` | `rollback`: восстановить из указанной резервной копии |
| `-y` | без подтверждения |

## 6. Обновление и откат

Обновление:

```bash
git pull
sudo ./deploy.sh plan
sudo ./deploy.sh install
```

Откат:

```bash
sudo ./deploy.sh rollback
# или из конкретной резервной копии:
sudo ./deploy.sh rollback --from-backup /root/ksc-integration-with-wazuh-siem-backups/<каталог>
```

В KSC: **Свойства Сервера администрирования → Экспорт в SIEM-систему** → «Экспортировать события в SIEM» → **Выключено** → «Сохранить».

## 7. Добавление нового типа события

1. Отметить событие для экспорта в KSC (раздел 3.2) и вызвать его на тестовом компьютере.
2. Снять событие на менеджере:
   ```bash
   sudo tcpdump -l -i any -nn -A -s0 'src host <KSC_IP> and tcp dst port 514' | tee /tmp/ksc-sample.txt
   sudo grep -aoE '<[0-9]+>1 .*<КОД_СОБЫТИЯ>.*' /tmp/ksc-sample.txt | head -1 | sed -E 's/^<[0-9]+>//' > tests/samples/<имя>.log
   ```
3. Посмотреть разбор: `sudo /var/ossec/bin/wazuh-logtest < tests/samples/<имя>.log`.
4. При необходимости добавить поля в `wazuh/decoders/kaspersky_ksc.xml` и **дочернее правило 100709** в `wazuh/rules/kaspersky_ksc_rules.xml` (ID 100700–100799).
5. Добавить ожидаемый результат в `tests/cases.json`, проверить `sudo ./deploy.sh test`, применить `sudo ./deploy.sh install`.
